# 101 ways to use this project for fun and profit

Use the Wix handbook to build one thing you want to open again tomorrow. Pick an idea, try it with a couple of sample records, and use the visible result below as your first acceptance check. These ideas are starting points you can adapt. The handbook supplies working patterns for the [greeting](04-site-development.md#build-a-button-that-calls-the-backend), [private records](the-missing-manual-to-velo.md#working-example-private-member-orders), [installed dashboard app](05-app-development.md), and [Headless reading list](06-headless.md).

Start with the editor and CMS for a single site. Add site code when a rule, private read, or recoverable action calls for it. Use an app if the feature needs to travel between installations, or Headless if a custom frontend solves a specific problem. [Choose your development path](01-platform-map.md)

## Pick up where you left off

1. **Resume button.** Open the homepage and jump to the last project you marked active.
2. **Project restart page.** See the source link, last decision, and next action together for one paused project.
3. **Dictated idea inbox.** Dictate a sentence, select Save, and find it at the top of the inbox after a reload.
4. **Effort picker.** Choose Light, Steady, or Deep and see one task you previously marked for that level of effort.
5. **Short codes for frequent links.** Enter a code like `notes` and open its saved destination.
6. **Reading bookmark.** Save a section link and return to that exact section the next day.
7. **Paused work list.** Filter paused projects and see the condition that would make each one worth restarting.
8. **Decision log.** Search for a project and find the choice you made, the reason, and the date.
9. **Repeatable setup.** Open a project card and copy its start command, with the working directory beside it.
10. **Saved search shelf.** Save a useful query and rerun it from a named button.

Use the private records recipe when the information belongs to a signed-in member. [Private records](the-missing-manual-to-velo.md#working-example-private-member-orders)

## Make the next action easier

11. **One-screen capture form.** Enter only a title and save a note under Unsorted for later review.
12. **Voice-friendly controls.** Say the visible name of a button in your voice control tool and invoke the intended action.
13. **Shortcuts with a visible alternative.** Activate the same command by keyboard shortcut or labeled button and see the same result.
14. **Keep the text after an error.** Force a failed save and retry with the original dictated text still in the form.
15. **Remember a preferred view.** Choose a compact or spacious layout and see the same choice when you return.
16. **Plain-language form errors.** Leave a required field blank and reach the field from an error message that says what to enter.
17. **Progress that can be heard.** Run a slow read and hear the final result or error announced while focus stays in place.
18. **Large-text reading page.** Increase text size and read the entire sample article with the primary controls still reachable.
19. **Review before a write.** Change one setting and see the proposed old and new values before confirming it.
20. **Readable personal export.** Download your own saved notes and open them in a text editor with titles and dates intact.

Try the action with the input method you actually use. [Accessibility checks](12-accessibility.md)

## Remove a repeated copy or paste step

61. **Repeat-safe import.** Import the same two sample records twice and finish with two rows.
62. **Review before syncing.** Compare two sample sources and see proposed additions and changes before writing either source.
63. **Manual CRM handoff.** Approve one synthetic inquiry, send it through a mock adapter, and reopen its saved export status.
64. **Provider acceptance receipt.** Simulate an HTTP 202 response and see Accepted while final completion stays pending.
65. **Retry a failed sync.** Force a temporary failure and recover the pending record using the same saved action key.
66. **Duplicate event check.** Feed the same synthetic event twice and see one processed receipt and one recorded side effect.
67. **Scheduled summary.** Process one bounded batch and reopen its saved checkpoint before the next batch.
68. **Freshness on an external lookup.** Show when a public value was last read and give a clear status when the provider is unavailable.
69. **Batch validation report.** Import one valid row and one invalid row and see the exact field that needs correction.
70. **Save an ambiguous outcome.** Simulate a timeout after submission and put the record in a review queue with its original request reference.

Use a mock provider until the real operation's permissions and response contract are defined. [Integration patterns](10-integrations.md)

## Learn by running one small experiment

91. **Greet from the backend.** Enter `Ryan` and see `Hello, Ryan.`. Try an empty value and see the validation message.
92. **Compare two editor models.** If you have both editors, build a read-only greeting with a Velo web method and a Studio Two endpoint and trace each call from the button to the backend.
93. **Practice safe display formatting.** Run the order formatter with its sample data and see `$24.50 USD`; switch to `--empty` and see `[]`.
94. **Build a recipe with its real dependencies.** Run the generated app or Headless build and see it finish with its Wix imports resolved. Record the project and dependency versions that worked.
95. **Verify refresh order.** Simulate a slow old search and a fast new search and see the newer result stay on screen.
96. **Check which fields leave the backend.** Read a synthetic record with an extra private field and see only the display fields in the response.
97. **Practice inspecting a preview.** Open a snapshot, make a second edit, and confirm the original preview still shows the earlier build.
98. **Audit a URL change.** Compare an old test route and its replacement and see the intended redirect and final page status.
99. **Practice recovery on a disposable copy.** Reopen a saved version and verify the critical page behavior and the current state of its sample records separately.
100. **Capture a reusable repair.** Reproduce one known fixture failure, record the smallest useful fix, and rerun the same action successfully.
101. **Return to the finished tool.** Open it from a bookmark or short command, do the task, close it, and resume from the saved result tomorrow.

Write down the one observation that would let you pick up the work again. [Workflow](02-professional-workflow.md) · [Testing](11-testing.md)
