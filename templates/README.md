# Project templates

Copy the smallest record that fits the job and replace the example facts. These are filled examples with synthetic site names, revisions, and outcomes; they are not evidence that a real project was tested or released. Remove irrelevant lines instead of completing an enterprise form.

| Need | Copy | Keep |
| --- | --- | --- |
| Define one change | [Feature brief](feature-brief.md) | Outcome, boundary, acceptance, recovery |
| Explain a consequential choice | [Decision record](decision-record.md) | Decision, reason, alternative, revisit trigger |
| Prepare/record a release | [Release record](release-record.md) | Source, destination, action, evidence, recovery |
| Recover from a failure | [Incident report](incident-report.md) | Impact, evidence, mitigation, verification, next action |
| Find/start/resume a project | [Project inventory](site-inventory.md) | Lane, owning state, commands, environment, recovery |

Use `unknown` or `pending` when evidence is missing. A saved local result is useful on its own; a template never authorizes publication, credential changes, or provider actions.
